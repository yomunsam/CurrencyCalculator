### 真机优先复测

1. 同一设备交替 touch、pen、鼠标和 Tab：仅 touch／pen 点金额打开内置键盘，第一次点非活动金额也应生效。
2. 输入 `(12+5)*18`：当前行只显示算式，其他币种实时换算；按 `=`／Enter 后同一行变为 `306`。检查中间插入、选区替换、退格、AC、除零和未闭合括号。
3. 点“系统键盘”：系统键盘能实际弹出，原文与光标不丢；打开“永不使用”，刷新后仍不弹内置键盘。
4. 手机竖横屏和宽屏：键盘不挡住正在编辑的金额，宽屏右下键盘不无限放大；设置与币种面板在右侧，搜索和长列表能滚动。检查浅色、深色、三语与放大文字。
5. 非活动金额长按／左滑、活动输入框选区、拖柄排序、复制值、最低两行限制与切换币种，确认原交互没有退化。

## 本轮实现

- 货币选择器：当前语言、英文名称、代码即时筛选；最近使用最多 3 项，剩余法币与加密币各按代码排序；无重复展示。
- 布局按宽度切换：窄屏底部面板，宽屏居中对话框。标题和搜索固定，列表滚动；关闭后归还焦点。
- 清空按钮位置保持固定，仅活动行显示；清空当前编辑金额时保留焦点。
- 行左侧拖柄兼操作菜单入口；鼠标右键、键盘菜单键或 Shift+F10 可打开菜单。金额输入框保留原生右键编辑菜单。
- 触控在币种信息或金额左侧空白处左滑展开删除，右滑或点击外部收起；长按约 550ms 打开行菜单。实际输入框收窄到金额文字附近并保留选区操作，拖柄负责纵向排序；最少保留 2 项。国旗不响应图片拖动或原生长按菜单。
- 取消拖动、捕获丢失不会提交；隔离其他指针。排序与删除按对象保持活动行和编辑行，切换币种不会重建整行。

## 2026-09-08 真机反馈修复

代码定位到滑动激活后转移指针捕获时，子元素冒泡的 `lostpointercapture` 被误判为整行丢失捕获，触发复位。现在仅在实际捕获目标失去捕获时取消；新增回归覆盖这一事件顺序。该机制与 iOS 反馈吻合，但修复仍需 iOS 真机复测，不能凭模拟测试认定全部解决。

开发现场使用临时参数监听局域网，不修改 launchSettings：

```sh
dotnet run --project Src/CurrencyCalculator.Web/CurrencyCalculator.Web.csproj --no-launch-profile --urls http://0.0.0.0:5085
```

复测优先检查：币种文字起滑不再回弹、中间空白左滑/长按、国旗长按不弹图片菜单、实际金额文字仍可编辑、非活动行清空按钮隐藏。

## Android 长按菜单后续修复

- 行菜单改为手动 popover，统一处理外部点击、Escape、操作完成和失去窗口焦点时关闭，避免打开菜单的那次触摸松手参与原生自动关闭。
- 长按触发后保留指针捕获，松手后才聚焦菜单；拦截这次触摸补发的点击。菜单自身也禁止文字选择和原生长按菜单。
- 新增“复制值”：复制该行当前实际数值，使用小数点，不包含币种、千分位、表达式或显示舍入。HTTPS 使用 Clipboard API；局域网 HTTP 使用页面复制动作，失败显示提示。
- 增加松手/补发点击及后续外部按下的模拟回归检查。本次按要求不进行浏览器交互测试，Android/iOS 效果和剪贴板行为交给真机验证。

非活动行普通文本的评估：有助于让金额区域参与行手势，并减少原生选区冲突；2–5 行没有值得追求的性能差异。需要共用排版与数值格式，并解决首次点击激活、键盘唤起及输入状态连续性。建议与后续输入交互一起落地，本次未切换输入模型。
