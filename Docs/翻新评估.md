# 翻新评估与后续顺序

本轮完成文档整理、PHP/KRW 及配套图标和静态汇率。以下为代码阅读后的建议，尚未实施，也未进行交互复现或性能测量。

## 1. 可搜索的货币选择器

现有 `CurrencySelectorOverlay` 已是自定义浮层：窄屏底部弹出，宽度达到 576px 时居中。可沿用布局基础，补齐搜索与对话框行为，不必引入组件库。

- 当前排序：排除已选币种 → 最近使用最多 3 个（最近在前）→ 其余法币按代码排序 → 加密币按代码排序。最近使用不是使用频率统计。
- 建议保留“最近使用”区，下面为“法币”“加密货币”，各按代码排序。暂不新增收藏或频率统计。
- 输入即时筛选代码、当前 UI 语言名称、英文名称，忽略大小写与首尾空格。搜索时展示去重后的结果，代码精确匹配置顶，并提供空结果文案。
- 窄屏底部面板、宽屏居中 modal，依据可用空间布局。搜索栏固定，列表独立滚动。
- 补齐标题、关闭按钮、Escape、焦点约束和关闭后焦点归还；触控打开时先不自动弹出系统键盘。

## 2. 删除与排序一并处理

- 清空按钮保持固定职责与位置，不再因活动状态变成删除按钮。
- 按事件的实际输入类型处理：触控横向左滑只展开删除按钮，点击才删除；鼠标右键打开行菜单。保留至少 2 项的现有限制。
- 为纯键盘提供可聚焦的行操作入口，支持菜单键或 Shift+F10；金额输入框保留原生文本编辑右键菜单。
- 纵向滚动、拖柄排序、横向删除分别限定起始区域和方向，避免输入框内选择文本触发滑动。同一时刻只展开一行。
- 当前拖动使用 Pointer Events，但没有跟踪活动 pointerId，`pointercancel` 还会调用提交排序。应先修复取消回滚、指针隔离和捕获丢失处理。
- 排序会调整 ActiveIndex，但编辑行索引未同步处理，需覆盖编辑中排序场景。用真实触控与鼠标复现后再判断其余问题。

## 3. 弱网可用性与轻量首屏优化

虽原始优先级较低，弱网影响日常可用性，建议在大型键盘改造之前解决。

- 已确认启动强制在线优先，两个在线源串行尝试；HttpClient 没有项目自定义超时，缓存和静态数据要等在线失败后才读取。建议先展示缓存或静态数据，再后台更新，并限制在线等待时间；刷新失败保留现有可用值。
- “点设置或刷新才显示”的现象尚未复现，不先归因为漏掉 StateHasChanged。检查异步状态更新、异常、存储写入和刷新完成通知。
- 历史缓存可能缺少新增币种，当前不会继续补齐；次级数据源也可能返回部分币种。需明确缺失数据策略，避免不完整快照挡住 fallback，更不能把旧值标为实时值。
- 当前新鲜度使用获取时间，而不是数据源日期。后续校正时区分数据日期与获取时间，避免旧报价显示为新鲜。
- 图标字体 CSS 来自外部 CDN，可考虑本地化或改为实际使用的本地 SVG，减少首屏与离线的外部依赖；先测量再做更大的加载优化。
- Service Worker 的子路径与版本切换另行验证；开发服务器启动不能证明发布版离线可用。

## 4. 内置计算器键盘单独一轮

建议延后。采用独立键盘组件和明确的编辑状态，不把按键处理继续塞进 Home。

- 触控进入金额编辑显示应用内键盘，清空后保持编辑；实体键盘继续直接输入。
- 支持数字、小数点、退格、清空、四则运算、括号和完成，复用现有表达式求值。
- 需要处理光标与选区、粘贴、负数、切换活动行、安全区、横屏及混合输入；不能只靠屏幕宽度或一次设备检测决定。
- 搜索框继续使用系统文本键盘，金额键盘状态与搜索分开。

重构随上述职责落地：先拆交互组件与状态，再删除多余封装；不做全项目格式重写或无收益的架构换代。后续交互改动需要浏览器和实际触控验收，本轮按要求暂不进行功能测试。
